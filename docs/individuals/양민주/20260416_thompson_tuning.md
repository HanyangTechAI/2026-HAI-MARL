- **파라미터**:
  - `reward_scale=12.0` (7.0 → 12.0, +71%)
  - `collision_penalty_rate=0.5` (유지)
  - `penalty_decay=0.96` (0.95 → 0.96, +1%)

**개선 포인트**:
- ✅ reward_scale을 높여 더 민감한 학습
- ✅ penalty_decay를 약간 높여 페널티 회복 속도 조절
- ✅ collision_penalty_rate는 유지하여 안정성 확보

**성능 분석**:
- 총 누적 보상에서 근소하게 개선 (+0.3%)
- 수렴 성능은 기본값과 동일
- 안정적이고 예측 가능한 성능

---

### ❌ 실패한 조합들

#### **공통 실패 패턴**
모든 실패 조합들이 **거의 동일한 낮은 성능** (33~34점)을 보임

**실패 조합 특징**:
1. `collision_penalty_rate < 0.5` (0.3 또는 0.4)
2. `penalty_decay > 0.95` (0.97 또는 0.98)

**실패 원인 분석**:

1. **너무 완화된 페널티** (`penalty_rate=0.3`)
   - 충돌 감지 후 페널티가 약함
   - 충돌이 많은 arm을 계속 선택
   - 슬리피지 문제 악화

2. **너무 빠른 페널티 회복** (`decay=0.98`)
   - 페널티가 너무 빨리 사라짐
   - 충돌 이력이 제대로 반영되지 않음
   - 같은 실수 반복

3. **조합의 상호작용**
   - 완화된 페널티 + 빠른 회복 = 페널티 무용지물
   - 충돌 감지 메커니즘이 사실상 작동하지 않음
   - 일반 Thompson Sampling보다 못한 성능

## 💡 핵심 교훈

### 1. **파라미터 민감도**

#### 높은 민감도 (성능에 큰 영향)
- ✅ `collision_penalty_rate`: **0.5가 최적**, 0.3~0.4는 실패
- ✅ `penalty_decay`: **0.95~0.96이 최적**, 0.97~0.98은 실패

#### 중간 민감도
- ⚠️ `reward_scale`: 7.0~12.0 범위에서 안정적, 너무 높거나 낮으면 위험

### 2. **파라미터 간 상호작용**

**성공 조합의 공통점**:
```python
collision_penalty_rate >= 0.5  AND  penalty_decay <= 0.96
```

**실패 조합의 공통점**:
```python
collision_penalty_rate < 0.5  OR  penalty_decay > 0.96
```

→ **두 조건을 모두 만족해야 함!**

### 3. **충돌 감지 메커니즘의 중요성**

Thompson Collision Aware의 핵심은 **충돌 감지와 회피**:
- 페널티가 너무 약하면 → 충돌 회피 실패
- 페널티가 너무 빨리 회복되면 → 이력 학습 실패
- 두 가지가 동시에 발생하면 → 알고리즘 붕괴

### 4. **개선 폭의 한계**

- 최고 개선: **+0.3%** (거의 무의미)
- Epsilon Greedy와의 격차: **-7.6%** (여전히 큼)
- UCB보다는 우수: **+32.1%**

→ **파라미터 튜닝만으로는 한계가 명확**
