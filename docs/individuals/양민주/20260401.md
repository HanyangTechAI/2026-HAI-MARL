# Thompson Sampling 구현 및 실험 결과
**Date:** 2026-04-01
**Author:** 양민주

## 1. 알고리즘 선택: Thompson Sampling

기존에 구현된 Epsilon-Greedy, UCB, Softmax, WSLS와 겹치지 않는 알고리즘으로 Thompson Sampling을 선택했다.
신경망 없이 구현 가능하면서도 이론적 배경이 탄탄한 베이지안 기반 밴딧 알고리즘이다.

## 2. Thompson Sampling 작동 원리

### 핵심 아이디어
각 arm이 얼마나 좋은지를 **확률 분포(Beta 분포)**로 표현하고, 매 스텝마다 각 arm의 분포에서 랜덤 샘플을 뽑아 가장 높은 arm을 선택한다.

### 구체적인 흐름
1. 초기 상태: 각 arm마다 Beta(1, 1) 분포 부여 (균등분포 = 아무 정보 없음)
2. 매 스텝:
   - 각 arm의 Beta(α, β)에서 숫자를 하나씩 샘플링
   - 가장 높은 샘플 값이 나온 arm을 선택
3. 보상 수신 후 업데이트:
   - 보상이 높으면 → α(성공 카운터) 증가 → 분포가 오른쪽으로 이동
   - 보상이 낮으면 → β(실패 카운터) 증가 → 분포가 왼쪽으로 이동

### 탐험/활용 균형이 자동으로 잡히는 이유
- 많이 선택한 arm → α, β가 커짐 → 분포가 좁아짐 → 평균 근처 값만 나옴 (활용)
- 적게 선택한 arm → α, β가 작음 → 분포가 넓음 → 가끔 높은 값이 튀어나옴 (탐험)

Epsilon-Greedy처럼 탐험 비율을 사람이 정하는 게 아니라, 데이터가 쌓이면서 자연스럽게 조절된다는 게 핵심.

### 슬라이딩 윈도우 변형
비정상(non-stationary) 환경 대응을 위해 `window_size` 옵션을 추가했다.
전체 히스토리 대신 최근 N스텝만 기억하여 환경 변화에 빠르게 적응하도록 설계.

## 3. 구현

`agents/thompson_sampling.py`에 구현. BaseAgent를 상속받아 `choice()`와 `getReward()`를 오버라이드.

두 가지 버전을 main_time.py에 등록:
- `Thompson` — 전체 히스토리 기억 (기본)
- `Thompson_W200` — 최근 200스텝만 기억 (비정상 환경 대응)

## 5. 결과 분석 및 자가 피드백

### Thompson이 UCB/Epsilon-Greedy에 밀린 이유

1. **스케일 문제**: 환경 보상이 GLOBAL_SCALER=0.0001로 스케일링되어 0~0.2 수준의 아주 작은 값이다. Thompson Sampling의 Beta 분포는 보상을 [0,1] 범위의 성공/실패로 해석하기 때문에, 대부분의 보상이 "거의 실패(β 증가)"로 처리되어 분포 업데이트가 비효율적이다.

2. **슬리피지(충돌 패널티) 회피 능력 부족**: 11개 에이전트가 동시 경쟁하는 환경에서 같은 arm에 몰리면 1/N^1.5 패널티가 적용된다. UCB는 탐험 보너스 구조 덕분에 자연스럽게 분산되지만, Thompson은 좋은 arm에 확률적으로 몰리는 경향이 있다.

3. **윈도우 버전(W200)이 기본 버전보다 낮은 이유**: 200스텝 윈도우가 이 환경의 변화 주기에 비해 너무 짧거나, 윈도우 리셋 시 정보 손실이 크기 때문으로 추정. 더 긴 윈도우(500, 1000)로 실험해볼 필요가 있다.

### Thompson이 Softmax/WSLS보다 나은 이유
- Softmax는 temperature 파라미터가 이 스케일에 맞지 않으면 과도한 탐험을 하게 됨
- WSLS는 근시안적(myopic) 행동 패턴이라 장기적 최적화에 불리
- Thompson은 불확실성 기반으로 자연스럽게 탐험/활용 균형을 맞추므로 중간 성적 유지

### 개선 방향
- Beta 분포 업데이트 시 보상 스케일을 보정하는 방법 검토 (예: 보상을 min-max 정규화)
- 윈도우 크기를 다양하게 실험 (500, 1000 등)
- 에이전트 수를 줄여서 슬리피지 영향 없이 순수 알고리즘 성능 비교 필요
