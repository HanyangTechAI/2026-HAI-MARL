# 📅 2026년 4월 16일 (목) 추가 작업 일지: MARL 하이퍼파라미터 튜닝의 한계와 역설

## 1. 개요 및 튜닝 시도
앞선 대규모 18개 에이전트 다자간 경쟁 시뮬레이션에서 1위를 차지했던 `DecayingEpsilonGreedy` 알고리즘의 성능을 극대화하기 위해 하이퍼파라미터 튜닝을 두 차례 진행했습니다.
1. **1차 시도 (소규모 맞춤형 Grid Search)**: `initial: 0.23, min: 0.02, decay: 0.93` 도출
2. **2차 시도 (18-Agent 풀 사이즈 Random Search)**: `initial: 0.54, min: 0.005, decay: 0.980` 도출

## 2. 최종 벤치마크 결과 및 참담한 실패
이러한 튜닝 모델들을 차례대로 전장에 투입시켜 본 결과는 당혹스러웠습니다.

| 버전 | 파라미터 조합 (initial, min, decay) | 누적 보상 | 최종 순위 |
| :--- | :--- | :--- | :--- |
| **튜닝 전 (원본)** | `0.50`, `0.010`, `0.995` | **29.92** | 1위 |
| **1차 튜닝** | `0.23`, `0.020`, `0.930` | 27.58 | 2위 |
| **2차 튜닝** | `0.54`, `0.005`, `0.980` | 26.02 | 5위 |

튜닝을 고도화할수록 성능이 개선되기는커녕 **오히려 순위와 누적 보상이 계속해서 추락**하는 역설적인 상황이 발생했습니다. 

## 3. 왜 튜닝할수록 성능이 더 떨어졌는가? (핵심 인사이트)
이번 실험은 Multi-Agent RL 환경에서 섣부른 하이퍼파라미터 최적화가 얼마나 위험해질 수 있는지를 적나라하게 보여줍니다.

1. **상호작용의 나비효과 (Slippage)**
   * 타 에이전트 17명의 행동이 내 보상을 깎아먹는(Collision) 이 MAB 환경에서는, 고정된 환경에 대한 최적화 방식을 적용할 수 없습니다. 
   * 파라미터를 미세하게 조정하여 "더 이성적인" 선택을 하도록 만들었더니, 오히려 타 에이전트들과 선택 타이밍이 똑같이 겹쳐버려 다 함께 공멸(Collision Penalty)하는 최악의 수로 작용했습니다.
2. **원래의 0.995 (원본)가 우승했던 진짜 이유**
   * 기존 0.995의 비상식적으로 느린 감쇠율(오랜 기간 랜덤 탐색)은 어떤 수학적 완벽함이 있어서가 아니라, 단순히 **"남들이 치열하게 싸울 때 바보처럼 다른 곳을 방황(탐색)했기 때문에 우연히 타격(충돌)을 피할 수 있었던 것"**입니다.
3. **결론: 혼전 속 오버피팅(Overfitting)의 위험성**
   * MARL 환경에서는 Search Script를 통해 나온 특정 Seed의 '수치적 최적화' 결과가 다른 무작위 변수 배치에서는 치명적인 과적합(Overfitting)으로 다가옵니다. 이번 튜닝의 참담한 하락세는 이를 명백히 증명하며, 다자간 혼돈 속에서는 무리한 튜닝보다 본연의 베이직한 구조 파악이 더 절실하다는 결론을 남깁니다.
